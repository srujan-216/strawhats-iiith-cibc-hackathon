### P5. Feature store and text features
1. src/layer3/features.py: each feature = SQL template + catalog entry in
   src/layer3/catalog.yaml (name, entity, type, meaning, recipe, sources, refresh, version,
   why). Same definition for build_offline(decision_dates) (point-in-time, only data before each
   date) and refresh_online()/get_online(keys) (latest values in gold.features_online).
   Features: dpd level and 3-month slope, worst dpd 12m, broken promises 90d, promise-due vs
   expected payday gap, payroll delay days, salary change 3m, NSF count 3m, cash-flow slope 6m,
   utilisation trend 6m, bureau delta 90d (non-quarantined), answer rate 30d, best time band,
   contacts last 7 days, balance at risk. No outcome columns, no protected/proxy columns.
2. Text features without bulk LLM: train TF-IDF (word + char n-grams, EN/FR) + logistic
   regression on the 500 public note labels and 500 transcript labels (5-fold CV); report
   precision/recall/F1 per field in reports/text_feature_eval.md; score all notes/transcripts on
   CPU in chunks. Optionally compare with Gemini on 50 labelled notes only.
3. Parity test (1,000 keys: offline at latest date == online). reports/feature_report.md
   (IV, correlation prune > 0.9, PSI < 0.2, kept list with reasons). `run.py features`.

### P6. NBA model, policy gate, explanations
1. Randomisation check on test_cell (SMD across cells); report.
2. Decision point = case open/review date; target = cure within 30 days. Map treatment codes
   to: no_contact, digital_nudge, call_best_time, payment_plan, hardship_referral,
   escalate (recommend only).
3. T-learner LightGBM (CPU), time-based split, seed 42; Qini/AUUC, calibration, uplift by
   decile and segment. If randomisation is weak, per-action propensity and say so.
4. Decision = argmax (p_a - p_no_contact) * balance_at_risk - cost_a under channel_capacity.
5. policy_gate.py: insolvency/deceased -> no contact; cease-contact/open dispute -> no
   contact; representative -> contact representative; consent per channel; contact cap;
   permitted hours in local time zone; hardship -> supportive actions only +
   hardship_programs eligibility; vulnerable -> supervisor queue. Blocked top action -> next
   allowed, with reason. One test per rule + "hardship never harsher".
6. explain.py: SHAP top 3 -> fixed plain-English templates + evidence ids + confidence +
   checks passed. score_case(case_id) under 1 s; batch-score open cases into
   gold.nba_recommendations.
7. reports/model_card.md. `run.py train`, `run.py score`. Add to `run.py all`.
